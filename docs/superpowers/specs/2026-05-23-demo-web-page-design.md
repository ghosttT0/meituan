# 指令遵循评估 Demo Web 页面设计

## 1. 目标

为当前“履约数字人外呼指令遵循自动评估系统”补充一个可直接演示的简易 Web 页面，用于替代 Swagger 作为首选展示入口。

该页面的目标不是完整后台系统，而是一个：

- 看起来像正式产品演示页
- 能直接运行现有评估链路
- 同时兼顾客户观感与技术验证
- 默认信息简洁，但支持逐层展开细节

的单页 Demo 驾驶舱。

---

## 2. 用户诉求总结

根据本轮讨论，页面需求已明确为：

1. **主要给当前项目 owner 自己看**，先确认整体成品感。
2. **页面表面要像给客户演示的产品**，不能像纯开发调试工具。
3. **细节要“收起来”**，需要时再展开查看。
4. **希望内容“全都放进来”**，既能看结论，也能看技术细节。
5. **页面需要铺满浏览器并自适应**，不能只是中间一小块 mockup。
6. **不再继续草图阶段**，后续直接实现真实页面。

---

## 3. 术语与交互模式

页面中“表面简洁、细节通过按钮收起来”的交互，在专业术语上主要对应：

- **Accordion**
- **Collapsible Sections**
- **Disclosure**

本设计统一采用 **Accordion（折叠面板）** 这个术语。

---

## 4. 页面定位

该页面定位为：

> **单页产品演示驾驶舱（Single-Page Demo Dashboard）**

它既不是管理后台，也不是纯原型页，而是：

- 首页就能体现结果价值
- 同时可以现场跑样例
- 还能按需展开技术细节

的一体化演示页。

---

## 5. 总体设计原则

### 5.1 客户风格优先

首屏先呈现：

- 总分
- 总体结论
- 风险/复核状态
- 维度评分卡

让人第一眼看到的是“评估结果”，不是 JSON 或规则表。

### 5.2 技术细节后置

以下内容全部默认折叠：

- 证据链
- 规则命中详情
- LLM 判分理由
- 原始结构化输出 JSON

### 5.3 默认可看，手动可试

页面默认进入预置案例模式，避免空页面。  
但也必须支持切换到手动试跑模式，让用户能粘贴任务指令与对话文本现场出结果。

### 5.4 铺满浏览器，自适应布局

页面整体要做成真正的 dashboard 风格：

- 宽屏铺满
- 中屏收缩
- 小屏堆叠

而不是固定宽度卡片居中。

---

## 6. 截图问题复盘与修正方向

从当前草图暴露的问题出发，正式页面需要修正：

### 6.1 对比度不足

截图中存在浅色文字叠在浅色卡片上的问题，导致：

- 总分难以识别
- 结论与状态不够突出
- Accordion 标签不够清晰

**修正方向：**

- 关键数字和主标题使用深色高对比文本
- 卡片背景保持浅色，但文本层级显式区分
- 折叠标题增加图标、边框和 hover 状态

### 6.2 页面不够“满”

草图结构正确，但视觉上仍偏“原型展示”，没有真实产品 dashboard 的舒展感。

**修正方向：**

- 顶部加入完整 header 区
- 主内容区采用全宽容器
- 左右区块按真实产品的栅格布局展开

### 6.3 信息层级不够抓眼

首屏虽然有“总分/结论/状态”，但视觉主次不够明确。

**修正方向：**

- 让总分成为第一视觉中心
- 总体结论与复核状态作为摘要卡并列出现
- 评分卡位于摘要之下，形成二级信息层

### 6.4 左侧输入区仍偏原型感

需要把左侧输入区从 mockup 样子，提升为正式产品输入面板。

**修正方向：**

- 使用真实表单组件风格
- 将预置案例与手动试跑切换设计为明确交互入口
- 输入区支持说明文案、清空、运行按钮

---

## 7. 页面信息架构

页面采用单页结构，分为四个主区域：

1. **顶部导航与模式操作区**
2. **左侧输入工作区**
3. **右侧结果摘要区**
4. **下方折叠细节区**

---

## 8. 页面结构设计

## 8.1 顶部 Header

顶部作为产品化外壳，负责建立“正式 demo 页面”的第一印象。

建议元素：

- 产品标题：`履约数字人外呼评估驾驶舱`
- 副标题：说明页面职责，例如“任务指令遵循自动评估 Demo”
- 右侧操作按钮：
  - 预置案例
  - 手动试跑
  - 导出结果

设计要求：

- 高度适中，不抢占纵向空间
- 采用浅蓝/浅灰渐变背景
- 保持企业产品感，而不是营销落地页感

---

## 8.2 左侧输入工作区

左侧固定为输入与案例工作区。

### 主要内容

1. **模式切换**
   - 预置案例模式
   - 手动试跑模式

2. **任务指令输入**
   - 文本域
   - 可回填预置样例

3. **对话转写输入**
   - 多行文本域
   - 允许粘贴多轮对话

4. **操作按钮**
   - 运行评估
   - 重置

5. **案例切换区**
   - 案例 1：收货时间确认
   - 案例 2：地址核验
   - 案例 3：异常异议处理

### 设计要求

- 宽屏时保持固定宽度，建议约 360~420px
- 面板风格统一、边界清楚
- 不使用原型风占位样式，使用正式表单外观

---

## 8.3 右侧结果摘要区

右侧是页面核心价值区。

### 第一层：结果摘要卡

包括：

- **总分**
- **总体结论**
- **复核状态**

其目标是让用户 3 秒内理解本次评估结果。

### 第二层：维度评分卡

展示关键评分维度，例如：

- 流程遵循
- 槽位收集
- 解释充分性
- 任务聚焦度

### 设计要求

- 总分卡必须最醒目
- 其余卡片信息清晰但不喧宾夺主
- 数值、标签、风险状态要有明确层级

---

## 8.4 折叠细节区（Accordion）

页面下半区用于承载技术和解释性内容。

默认全部收起，点击后展开。

### Accordion 列表

1. **证据链**
   - 轮次编号
   - 证据原文
   - 对应结论

2. **规则命中详情**
   - 规则 ID
   - 是否通过
   - 扣分原因
   - 命中轮次

3. **LLM 判分理由**
   - 维度
   - 分数
   - 理由
   - 证据

4. **原始 JSON / 技术细节**
   - 原始结构化输出
   - run_id
   - spec_id
   - confidence

### 设计要求

- 折叠标题必须清晰可点
- 展开/收起要有图标状态变化
- 展开内容采用清爽的结构化排版

---

## 9. 交互流程设计

页面支持两种使用路径。

### 9.1 默认预置案例路径

1. 页面加载后自动展示一个预置案例
2. 输入区自动回填任务指令和对话样例
3. 结果区自动展示样例评估结果
4. 用户可切换不同预置案例

### 9.2 手动试跑路径

1. 用户切换到手动试跑模式
2. 输入任务指令与对话文本
3. 点击“运行评估”
4. 页面调用后端 API
5. 结果区与 Accordion 同步刷新

---

## 10. 响应式布局策略

页面需要支持从桌面宽屏到窄屏的平滑退化。

### 10.1 宽屏

- 左侧固定输入区
- 右侧自适应结果区
- Accordion 横向铺满结果区宽度

### 10.2 中屏（笔记本）

- 保持双栏
- 左栏略收窄
- 右栏保持结果优先

### 10.3 窄屏 / 小窗口

- 自动改成上下堆叠
- 上方输入区与案例区
- 下方结果摘要与 Accordion

### 响应式原则

- 不强行维持双栏
- 不让评分卡挤压变形
- Accordion 在小屏下仍然是默认收起

---

## 11. 视觉风格设计

### 11.1 色彩

建议采用：

- 浅灰白作为主背景
- 浅蓝作为主强调色
- 深色文本作为主要信息色
- 轻微渐变用于摘要头部区域

### 11.2 气质

页面风格应当是：

- 企业级
- 可信
- 专业
- 克制

避免：

- 过度营销感
- 过重装饰
- 过于原型化的占位风格

### 11.3 视觉重点

首页视觉优先级：

1. 总分
2. 结论 / 复核状态
3. 维度评分卡
4. 细节折叠区

---

## 12. 技术实现方案

采用已确认的方案：

> **FastAPI 下挂轻量 SPA 单页**

不新建独立 React/Vue 工程，而是在现有后端项目内直接交付一个轻量前端页面。

### 结构建议

- `app/api/routes_demo.py`
  - 提供 demo 页面路由
- `app/web/demo.html`
  - 页面结构
- `app/web/demo.css`
  - 页面样式
- `app/web/demo.js`
  - 页面交互逻辑

### 后端复用接口

直接复用现有接口：

- `POST /specs/compile`
- `POST /evaluations/run`
- `GET /evaluations/{run_id}`

第一版直接在前端本地维护预置样例数据，不新增预置案例后端接口。

---

## 13. 第一版功能边界

### 第一版必须包含

1. 单页 dashboard 式页面
2. 顶部产品级 header
3. 预置案例切换
4. 手动试跑
5. 结果摘要卡
6. 维度评分卡
7. Accordion 细节区
8. 响应式布局

### 第一版可以不做

1. 复杂登录权限
2. 历史记录列表
3. 多页面导航
4. 图表系统
5. 真正的客户级品牌视觉规范系统

---

## 14. 验收标准

页面达到第一版验收条件，当且仅当：

1. 打开页面后即可看到完整产品化 demo 布局；
2. 宽屏下页面能铺满浏览器并保持双栏结构；
3. 默认存在预置案例；
4. 用户可切换到手动试跑模式；
5. 点击运行评估后可展示真实评估结果；
6. 技术细节均通过 Accordion 折叠展示；
7. 小屏下布局能自动堆叠且不混乱。

---

## 15. 关键决策总结

1. 页面定位为**单页产品演示驾驶舱**。
2. 页面风格采用**客户可展示风格**，而不是纯调试工具。
3. 首屏采用**左输入、右结果**的平衡型结构。
4. 页面支持**预置案例 + 手动试跑**双模式。
5. 细节统一使用 **Accordion** 折叠承载。
6. 页面实现采用 **FastAPI 下挂轻量 SPA**。
